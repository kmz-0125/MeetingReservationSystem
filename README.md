# １．MeetingReservationSystem(会議室予約システム)  
ASP.NET Core MVC で作成した、社内向けの会議室予約システムです。  
学習用のポートフォリオとして、設計(テーブル・ルールの言語化)から実装までを、段階的に進めています。  
> [!WARNING]
> **現在開発中です。** 実装済みの機能と未実装の機能は「4. 機能一覧と実装状況」に記載しています。

# ２・作成の目的  
前作(TaskManager)で、次の課題が見つかりました。  
- 学んだルールを、新しい場面に自分で適用することが苦手
- ゼロから設計して手を動かす「初速」が弱い

この課題を克服するため、**別設計のアプリを、設計メモを先に書いてから実装する**流れで作っています。  
(`SaveChangesAsync` の呼び忘れ、代入の向き、`DateTime` の Kind 不一致、といった前作の失敗パターンが減っているかを、成長の指標にしています。)

# ５．設計のポイント  
【テーブル構成】  
AspNetUsers(Identity　FamilyName・FirstName・DepartmentId を追加)  
Departments(部署)  
Rooms(会議室・定員・Capacity)  
Reservations(予約)  
```
Departments  1 ──< AspNetUsers  1 ──< Reservations >── 1  Rooms
```

外部キーの削除時の動作は、すべて Restrict(紐づきがある間は削除を拒否)にしています。  
予約のキャンセルは、削除ではなく IsCancelled フラグで管理する設計です。  
会議の状態(開始前・会議中・終了)は、DBに持たず、開始・終了時刻と現在時刻から計算する設計です。  

【時刻の扱い】  
画面の入力は日本時間(DateTime)、DBは timestamptz(UTC / DateTimeOffset)です。  
変換は TimeHelper(ToUtcFromJst / ToJstFromUtc)の1か所にまとめています。  
予約の終了時刻は「その時刻を含まない」扱いにしています(10:00〜11:00 と 11:00〜12:00 は重ならない)。  

【予約の重複判定(設計済み)】  
> 重なる = (新しい予約の終了 > 既存の開始) かつ (新しい予約の開始 < 既存の終了)  

同じ部屋・キャンセル済みを除く・編集時は自分自身を除く、という条件を加えます。  
比較はUTCにそろえた値で、DB側(SQL)で行います。  

# ６．動かし方  
【前提】  
.NET SDK/PostgreSQL  

【手順】  
１．リポジトリを取得する。  
２．接続文字列をユーザーシークレットに設定する。  
   ```
   dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Host=localhost;Port=5432;Database=MeetingReservationSystemDb;Username=<ユーザー名>;Password=<パスワード>"
   ```
３．マイグレーションを反映する。  
   ```
   dotnet ef database update
   ```
４．起動する。  
   ```
   dotnet run
   ```
